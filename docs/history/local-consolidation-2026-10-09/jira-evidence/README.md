# Cópias documentais do levantamento Jira/Confluence de 01–02/10/2026

Preparação em 09/10/2026 por CODEX para o commit conjunto solicitado. Este diretório contém onze
representações minimizadas dos registros históricos omitidos da entrega pública, além da fonte
textual de um script local de uso único. Os documentos e snapshots canônicos integrados continuam
sendo a referência do projeto.

Os originais foram lidos do backup local verificado por SHA256 em
`.cache/local-backups/consolidation-20261009/jira`, conforme o manifesto local. Cada origem foi
conferida antes da criação da cópia. O backup mantém os valores originais e fica fora do commit.

Nomes e identificadores de conta foram substituídos pelos papéis já definidos na
[responsabilidade por evidência](../../../../specs/011-jira-confluence-organization/evidence/responsibility-proposal.md):
responsável técnico 01, responsável técnico 02 e solicitante do modelo externo. A conexão de serviço
recebe o rótulo “conexão técnica histórica”. O vínculo entre identificador e papel foi extraído do
levantamento original; a identidade atual da sessão não foi atribuída a pedidos passados. JSON foi
transformado recursivamente, mantendo sua estrutura, fatos, códigos, datas, estados e autoria IA.
Valores identificadores nas URLs também foram minimizados; essas URLs não servem para executar
consultas ou operações.

Estas cópias são documentos derivados e não comprovam a identidade nominal, uma consulta atual,
permissões vigentes, novas atribuições, nova aplicação de operações, homologação ou publicação
remota. Não são cargas prontas para reaplicação no Jira/Confluence. Os limites da entrega anterior
permanecem na
[revisão pública de 07/10](../../../../specs/011-jira-confluence-organization/evidence/public-review-2026-10-07.md).

`render-approved-pages.cjs.txt` conserva a fonte histórica como texto: possui caminho local e
produzia HTML a partir dos corpos aprovados naquele levantamento. Não foi executado nesta
consolidação; a extensão textual evita ativá-lo como ferramenta ou código do projeto. Os JSON de
páginas usados como entrada e saída continuam no diretório canônico da spec 011.
